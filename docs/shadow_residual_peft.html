Shadow Residual as a PEFT Module

Shadow residual is a Granite Switch decoder-layer architecture that runs two hidden state streams in parallel and lets the trained adapter trunk consult a frozen base trunk through a per-layer Wcross connection. The base trunk is the unadapted base model's Q/K/V/O/MLP trajectory bit-for-bit — there are no K/V exceptions: each stream computes its own K/V from its own normed input under its own stream context, and writes into its own KV cache (§9.4). The frozen-base invariant is enforced by a custom PEFT wrapper (ShadowResidualLora) that gates the LoRA delta off when the decoder calls a projection on behalf of the base stream. The factory always builds ShadowResidualForCausalLM; when cross_stream is not in target_modules, the forward takes an adapter-only early-exit (§9.3) — a single Q/K/V/O/MLP pass per layer with the LoRA delta firing, no base-stream compute at all.

1. What shadow residual is

The shadow residual decoder layer maintains two parallel hidden state streams through every transformer block:

  • hbase — the frozen base trunk. Bit-equivalent to running the unadapted base model's Q/K/V/O/MLP forward at every layer. Enforced by a custom PEFT wrapper (ShadowResidualLora) that detects which stream the decoder is currently computing for via a contextvar, and returns base_layer(x) only — no LoRA delta, no ALORA, no DoRA — when the active stream is "base". K/V is no exception: each stream now has its own K/V projections (called under its own stream context) and its own KV cache. See §9.4.
  • hadapt — the adapter trunk. Same shape as hbase; receives LoRA contributions on every wrapped projection (Q/O/MLP) plus the cross-stream injection at end-of-layer. Q/O/MLP wrappers fire here because the decoder calls them under stream_context("adapter").

Per-projection summary of the frozen-base invariant:

ProjectionBase callAdapter callCache identity
q_proj / o_projdelta gated offdelta firesn/a
gate_proj / up_proj / down_projdelta gated offdelta firesn/a
k_proj / v_projdelta gated off (on normed_base)delta fires (on normed_adapt)two disjoint caches: past_key_values_base holds Wkv·normed_base (frozen), past_key_values holds whatever the adapter produces from normed_adapt

At the end of each layer, an optional low-rank Wcross connection injects information from the base stream into the adapter stream: 

h_adapt += B (A · h_base)        # A: (R, H), B: (H, R), R ≪ H

This is the cross-stream term. It lets the adapter trunk consult the frozen base trunk's representation at every layer, rather than only at the start.

2. The dual-stream forward pass

Every projection in the SR decoder layer is a _StreamGatedLinear (a marker subclass of nn.Linear) with a standard name (q_proj, k_proj, v_proj, o_proj, gate_proj, up_proj, down_proj). The factory registers {_StreamGatedLinear: ShadowResidualLora} with the LoraConfig, so PEFT wraps any subset the user lists in target_modules with the SR-aware wrapper instead of stock peft.tuners.lora.Linear. When ALORA is enabled, every wrapped projection still gets stock ALoraLinearVariant behaviour (because ShadowResidualLora subclasses stock peft.tuners.lora.Linear) — the only behavioural difference is the per-call stream gate at the top of forward.

The dual-stream forward runs two parallel attention calls with disjoint K/V. Every projection — Q, K, V, and O — is called twice: once inside stream_context("base") on normed_base with the LoRA delta gated off, and once inside stream_context("adapter") on normed_adapt with the delta firing. Each stream writes its own K/V into its own DynamicCache (past_key_values_base for the frozen base, the user-facing past_key_values for the adapter), and each attention call reads only from its own cache.

The diagram shows the dual-stream path. When no CrossStream site has a CrossStreamLora installed, the runtime early-exit (§9.3) collapses this to the adapter column only — not the base column. The base stream exists to be consumed by cross_stream; without a cross-stream wrapper there is nothing to consume it, so we skip its compute entirely and run a single Q/K/V/O/MLP pass with the LoRA delta firing. The result is "LoRA on the SR architecture without cross-stream", equivalent in compute to plain LoRA on Granite Switch.

Things to notice:

  1. Frozen-base invariant for Q/O/MLP. The base call to every wrapped Q/O/MLP projection runs inside stream_context("base"). The ShadowResidualLora wrapper checks the contextvar at the top of forward and returns base_layer(x) without applying any LoRA delta. The base trunk is therefore bit-equivalent to the unadapted base model's Q/O/MLP forward — which is exactly what the cross-stream edge is supposed to consult.
  2. K/V participates in the frozen-base invariant. k_proj and v_proj are stream-gated exactly like Q and O: each stream calls them under its own stream_context on its own normed input, and each stream writes its result into its own DynamicCache. The base attention reads past_key_values_base (which holds Wkv·normed_base, frozen and adapter-free); the adapter attention reads past_key_values (which holds whatever the adapter produces from normed_adapt — including any K/V LoRA delta the user configured). The two caches are completely disjoint, so K/V LoRA on the adapter cannot leak into the base trunk's attention reads.
  3. Cross-stream is the only base→adapter coupling point. Within each layer, the only way information moves from the base trunk to the adapter trunk is through the rank-R Wcross projection at the end: h_adapt += W_cross(h_base). The cross-stream injection is the per-layer base→adapter merge. After the last layer the adapter stream is normed and projected directly: hidden_states = self.norm(h_adapt). The previous final-step gate torch.where(adapter_indices > 0, h_adapt, h_base) was vestigial GraniteSwitch routing — it severed autograd from the LoRA delta in unconditional adapter training and has been removed.
  4. K/V LoRA and Wcross can be trained together. Listing ["q_proj", "k_proj", "v_proj", "o_proj", "cross_stream"] is a fully supported configuration — every wrapped projection is stream-gated (delta off on the base call, fires on the adapter call), the per-stream caches keep the base trunk pristine, and the rank-R cross-stream edge runs in parallel at end-of-layer. See §6 for the canonical example.

3. Why this fits standard PEFT now

The pre-refactor SR design carried its LoRA as raw nn.Parameter tensors (q_lora_A/q_lora_B/o_lora_*/gate_up_lora_*/down_lora_*) applied via inline apply_lora_delta calls. That collided with stock PEFT in two ways: (a) there were no nn.Linear child modules to wrap with peft.tuners.lora.Linear; and (b) any user who did add PEFT LoRA on top would end up with two parallel LoRA pathways on the same projection, both modifying the base stream. The refactor deletes the SR-native pathway entirely.

After the refactor, the only mismatch left between SR and stock PEFT is the cross-stream injection — there's no nn.Linear for PEFT to wrap there because the operation is base→adapt, not input→output. That gap is closed by adding a CrossStream no-op nn.Module as the targetable site, plus a CrossStreamLora custom PEFT layer that PEFT installs in its place.

4. The PEFT integration

4.1 Cross-stream becomes an nn.Module

class CrossStream(nn.Module):
    """No-op site that PEFT can wrap with a CrossStreamLora layer."""
    def __init__(self, hidden_size: int):
        super().__init__()
        self.in_features = hidden_size
        self.out_features = hidden_size
        # Anchor for PEFT's device-dispatch in _replace_module.
        self.register_buffer("_device_anchor", torch.zeros(1), persistent=False)

    @property
    def weight(self): return self._device_anchor

    def forward(self, h_base, *args, **kwargs):
        return torch.zeros_like(h_base)

The decoder layer holds self.cross_stream = CrossStream(H) and its forward calls h_adapt = h_adapt + self.cross_stream(h_base). By itself the contribution is zero — the module is a target, not a parameter source. The rank-R A and B live on whatever PEFT installs in its place.

Why the device anchor? peft.tuners.lora.LoraModel._replace_module calls next(child.parameters()) as a fallback when wiring up installed adapter weights to the right device. A parameter-free CrossStream would raise StopIteration. The one-element _device_anchor buffer sidesteps that without adding any trainable weight.

4.2 CrossStreamLora — a custom LoRA layer

The wrapper PEFT installs at every cross_stream site is a CrossStreamLora(nn.Module, LoraLayer). It mirrors stock peft.tuners.lora.Linear in storage and save/load surface, and additionally consumes alora_offsets for ALORA-style mid-sequence gating (see §5):

  • Storage: self.lora_A and self.lora_B are nn.ModuleDicts keyed by adapter name. Each holds an nn.Linear(H, r) / nn.Linear(r, H) pair (no bias).
  • Init: A with kaiming_uniform_, B with zeros — so the cross-stream contribution starts at exactly zero.
  • Forward: base(x) + Σactive Ba(Aa(dropout(x))) · scalinga · mask. base(x) = 0, so the result equals the rank-R cross-stream projection (gated by alora_offsets if ALORA is configured, full-on otherwise).
  • Save/load: the nn.ModuleDicts round-trip through peft.PeftModel.save_pretrained / from_pretrained — the cross-stream weights live in the standard adapter_model.safetensors, no SR-specific sidecar.
  • merge / unmerge: no-ops. There is no base weight to fold the adapter into; get_delta_weight still returns the rank-R outer product for tooling that wants to inspect the effective weight.

Registration happens via PEFT's experimental hook: 

from peft import LoraConfig, get_peft_model
from granite_switch.experimental.shadow_residual.cross_stream import CrossStream
from granite_switch.experimental.peft_shadow_residual import CrossStreamLora

config = LoraConfig(
    r=32, lora_alpha=32,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj", "cross_stream"],
    rank_pattern={"cross_stream": 96},   # override per-site rank
    alpha_pattern={"cross_stream": 96},  # override per-site alpha
    alora_invocation_tokens=[100264, 78191, 100265],  # optional ALORA gate
    task_type="CAUSAL_LM",
)
config._register_custom_module({CrossStream: CrossStreamLora})
peft_model = get_peft_model(sr_base_model, config)

PEFT's _create_and_replace consults config._custom_modules first when dispatching, so any CrossStream instance whose attribute name matches cross_stream in target_modules gets replaced with a fresh CrossStreamLora wrapper. r and lora_alpha for that site are resolved from rank_pattern / alpha_pattern exactly like for any other LoRA target.

4.3 The factory: one entry point, one base architecture

get_shadow_residual_peft_model(base_id, lora_config) always builds the same base — ShadowResidualForCausalLM. _build_sr_base loads upstream GraniteMoeHybridForCausalLM.from_pretrained directly, instantiates a fresh ShadowResidualForCausalLM(config), and uses transfer_base_weights to slice fused projections (shared_mlp.input_linear → gate_proj/up_proj; attention is already unfused upstream) into the SR layout. There is no GraniteSwitch composer call, no SingleSwitch, no adapter_token_ids buffer, and no built-in LoRA tensors. After the base is built, the factory calls stock peft.get_peft_model. There is no factory-level branch on whether "cross_stream" is in target_modules; the unified flow handles both cases through one architecture. CrossStreamLora and ShadowResidualLora are registered unconditionally, so PEFT picks them up whenever the user lists cross_stream or a stream-gated projection as a target and ignores them otherwise.

Whether the dual-stream forward actually runs is a runtime decision, not a construction-time decision: at the top of every forward, the SR model checks whether any CrossStream site has an active CrossStreamLora wrapper installed with non-zero rank. If none does, the dual-stream path is skipped and each decoder layer runs in single-stream mode (one Q/O/MLP forward per layer, identical compute to plain Granite). See §9.3 for the early-exit details.

User configArchitecture builtForward path taken
"cross_stream" in target_modules ShadowResidualForCausalLM + dual-stream forward. Stock peft.tuners.lora.Linear wraps every other listed projection (q_proj/k_proj/…); ALoraLinearVariant attaches automatically when alora_invocation_tokens is set; CrossStreamLora handles each cross_stream site.
"cross_stream" absent ShadowResidualForCausalLM (same class, same construction) Adapter-only early-exit: only h_adapt is computed per layer with the LoRA delta firing; the base stream is not maintained, the second Q/O/MLP forward is skipped, and the cross_stream call is skipped. Compute equals plain-Granite + the wrapped LoRA deltas — no dual-stream overhead.

Consequences of unifying:

  • One code path to maintain. The factory does not branch; the loader does not branch. The only conditional is the runtime check in the SR forward (§9.3).
  • Cross-stream is always reachable. A user who trains without cross-stream can later add a cross-stream adapter (add_adapter with a config that includes cross_stream) without rebuilding the model — the CrossStream sites are already in the module tree, just unwrapped.
  • Save/load is uniform. load_shadow_residual_peft_model always builds the SR base; the saved adapter_config.json still records whether cross_stream was a target, and the runtime early-exit takes care of the rest.
  • Bit-equivalence to plain PEFT when no cross-stream is configured holds because the early-exit branch runs the exact same per-layer compute as a plain Granite forward with PEFT-wrapped projections. The SR scaffolding (the CrossStream sites themselves, plus the _StreamGatedLinear wrappers around projections) is constructed but not invoked on the hot path.

There is no "freeze SR built-in LoRA tensors" post-pass. The SR-native LoRA pathway is gone, so PEFT's own freeze logic (only modules it wrapped get requires_grad) is sufficient. Construction no longer routes through GraniteSwitchComposer at all: there are no SwitchedLoRA wrappers, no SingleSwitch, no adapter_token_ids, no num_adapters placeholder. _build_sr_base loads upstream GraniteMoeHybridForCausalLM and transfer_base_weights slices its fused MLP into the unfused SR layout in one step.

5. Mid-sequence adapter activation (ALORA)

SR-PEFT is ALORA-class: the adapter contributes nothing on tokens before the activation marker, and full delta on tokens at and after the marker. With peft 0.19.1 this is provided by the library out of the box for every wrapped nn.Linear — set LoraConfig.alora_invocation_tokens=[ids…] and stock ALoraLinearVariant is auto-attached to every wrapped projection. PEFT auto-computes per-row alora_offsets from input_ids at the top of PeftModel.forward and injects them into every LoraLayer via a pre-forward hook.

CrossStreamLora participates in the same flow. Because it inherits LoraLayer, it receives alora_offsets via the same hook. Its forward gates the cross-stream delta to the trailing T - offsets[i] positions per row, mirroring ALoraLinearVariant.forward: 

def forward(self, x, *args, alora_offsets=None, **kwargs):
    result = self.base_layer(x, *args, **kwargs)         # zeros
    if self.disable_adapters or self.merged:
        return result
    B, T, _ = result.shape
    if alora_offsets is None:
        mask = torch.zeros((B, T), dtype=torch.bool, device=result.device)
    else:
        offsets = torch.tensor(
            [0 if o is None else min(int(o), T) for o in alora_offsets],
            device=result.device, dtype=torch.long,
        )
        pos = torch.arange(T, device=result.device).unsqueeze(0)
        mask = pos >= (T - offsets).unsqueeze(1)
    for active in self.active_adapters:
        if active not in self.lora_A: continue
        delta = self.lora_B[active](self.lora_A[active](
            self.lora_dropout[active](self._cast_input_dtype(x, self.lora_A[active].weight.dtype))
        )) * self.scaling[active]
        result = result + delta * mask.unsqueeze(-1).to(delta.dtype)
    return result

The SR architecture itself sees nothing — no mask is computed in our decoder layer, no activation kwarg threads through SR-side code. PEFT drives gating end-to-end. alora_invocation_tokens is a stock LoraConfig field, so it round-trips through adapter_config.json automatically; the standalone loader picks it up without any custom parsing.

Bit-identity guarantee. For pre-marker positions, every wrapped projection's delta is zero (ALoraLinearVariant) and the cross-stream delta is zero (CrossStreamLora's trailing-positions mask). The dual-stream forward therefore produces logits at pre-marker positions equal to the unadapted base model's logits at those positions, modulo small reduction-order differences from running per-stream Q/K/V/O/MLP twice through the SR layernorm/cat fused path.

6. What the user gets

The factory call is the same in both cases — the only difference is whether cross_stream appears in target_modules: 

# With cross-stream: dual-stream forward, ALORA-gated, base→adapter coupling.
config = LoraConfig(
    r=32, lora_alpha=32,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj", "cross_stream"],
    rank_pattern={"cross_stream": 96},
    alora_invocation_tokens=[100264, 78191, 100265],
    task_type="CAUSAL_LM",
)
model = get_shadow_residual_peft_model("ibm-granite/granite-4.1-3b", config)

# Without cross-stream: same factory call, same base class, but the
# runtime takes the single-stream early-exit path inside every layer —
# zero dual-stream overhead.
config = LoraConfig(
    r=32, lora_alpha=32,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    task_type="CAUSAL_LM",
)
model = get_shadow_residual_peft_model("ibm-granite/granite-4.1-3b", config)

In both cases:

  • The base model is ShadowResidualForCausalLM — same class, same construction. There is no separate "vanilla" code path.
  • r, lora_alpha, lora_dropout, use_rslora, rank_pattern, alpha_pattern all behave the standard way.
  • save_pretrained / from_pretrained / add_adapter / set_adapter / print_trainable_parameters all work because the result is a real peft.PeftModel.
  • Without cross_stream, the runtime takes the adapter-only early-exit (§9.3): one Q/K/V/O/MLP pass per layer with the LoRA delta firing on every wrapped projection. Output is equivalent to running stock PEFT against a plain Granite base (modulo small reduction-order differences from the SR layernorm/cat path being absent in this branch).
  • With cross_stream, the dual-stream cost (≈2× attention + MLP work) is only paid on the layers and tokens where the cross-stream contribution is actually nonzero — i.e. while cross-stream is being trained or applied.
Caveat — experimental PEFT API. LoraConfig._register_custom_module is documented as experimental in PEFT and could change between versions. The integration is pinned to PEFT 0.19.x. If/when PEFT graduates the API, expect a small change to the registration call site.

6a. Wired into train.py and the answerability eval

The internal training entry point granite_switch.experimental.training.train is PEFT-only after the refactor. The legacy non-PEFT direct-composer branch and the freeze_except_lora helper are gone. Flags translate directly into target_modules:

  • --attn_lora True → adds q_proj, k_proj, v_proj, o_proj
  • --mlp_lora True → adds gate_proj, up_proj, down_proj
  • --cross_stream True → adds cross_stream
  • --cross_stream_rank R → rank_pattern["cross_stream"] = R (default 96)
  • --alora_invocation_token_ids "id1,id2,id3" → alora_invocation_tokens=[...]

The build path:

  1. _build_lora_config assembles a stock LoraConfig from those flags.
  2. get_shadow_residual_peft_model always builds ShadowResidualForCausalLM via _build_sr_base (upstream HF load + transfer_base_weights) and registers both CrossStream → CrossStreamLora and _StreamGatedLinear → ShadowResidualLora. Whether the dual-stream forward actually runs at training time is decided by the runtime early-exit (§9.3) — if cross_stream isn't in target_modules, every forward takes the single-stream path with zero dual-stream overhead.
  3. Training proceeds as normal with HF Trainer; PEFT manages requires-grad and the saved layout is the standard adapter_config.json + adapter_model.safetensors pair.
  4. On completion, model.save_pretrained(output_dir).

The companion eval script experiments/scripts/answerability_eval.py uses a single call: 

from granite_switch.experimental.peft_shadow_residual import load_shadow_residual_peft_model

model = load_shadow_residual_peft_model(
    base_model_name_or_path=args.base_model,
    checkpoint_path=args.checkpoint_path,
    torch_dtype=torch.bfloat16,
)

The loader reads LoraConfig.from_pretrained(checkpoint_path), always builds the SR base via _build_sr_base, registers CrossStreamLora, and calls PeftModel.from_pretrained. alora_invocation_tokens is read from the saved config automatically. The runtime early-exit on the loaded model takes care of the no-cross-stream case — the loader does not need to branch on target_modules. Old SR-native checkpoints (pre-refactor) are no longer loadable; that's intentional.

8. What's deliberately NOT in this design

  • SR-side LoRA tensors — gone. q_lora_*, o_lora_*, gate_up_lora_*, down_lora_*, apply_lora_delta, and lora_functional.py have all been removed. Q/K/V/O/MLP LoRA is plain stock PEFT against standardly-named projections.
  • Custom ALORA gating — gone. There is no ActivationGatedLora wrapper, no SR-side mask computation, and no per-call activation kwarg in the SR forward. Stock peft 0.19.1's ALoraLinearVariant handles every wrapped projection automatically; CrossStreamLora reads alora_offsets from the same pre-forward hook.
  • Doubled-Q-heads attention fusion — gone. Two parallel attention forwards with per-stream K/V is simpler and correct now that there's no SR-native LoRA delta to share via head-doubling, and the per-stream caches keep the base trunk adapter-free.
  • vLLM SR-LoRA path — deprecated. punica_delta.py raises NotImplementedError.
  • merge_and_unload — intentionally disabled. The factory and loader override merge_and_unload / merge_adapter / unmerge_adapter on the returned PEFT model to raise NotImplementedError. Folding the adapter delta into the base linear would silently break the frozen-base invariant — the next forward call's stream_context("base") would no longer return the unadapted base model's output. Save/load round-trips through save_pretrained / load_shadow_residual_peft_model are unaffected (they go through the state-dict path, not merge).

9. Gotchas

Things that look like simplifications but aren't, and behaviors that surprise readers expecting a "thinner" SR-PEFT integration.

9.1 Why h_adapt can't reuse stock PEFT verbatim

A natural question on first read: if every other projection is plain stock PEFT, why does the cross-stream site need its own CrossStream + CrossStreamLora pair? Why not just point target_modules at an existing nn.Linear and let peft.tuners.lora.Linear do the work?

The shape mismatch. Stock peft.tuners.lora.Linear wraps an existing nn.Linear and computes out = base_layer(x) + B(A(x)) * scaling: one input, one output, both flowing through the same underlying linear. Cross-stream is shaped h_adapt = h_adapt + B(A(h_base)) * scaling — the input (h_base) and the destination (h_adapt) live on two different residual streams. There is no nn.Linear in the SR decoder whose (input, output) pair corresponds to (h_base, h_adapt); the two streams are independent accumulators, coupled only by this rank-R edge at end-of-layer (decoder_hf.py:145). PEFT's "find an nn.Linear named X and replace it" rule cannot synthesize a new edge between two tensors; it can only intercept an existing one.

Why CrossStream can't be deleted. CrossStream is ~30 lines and contributes zero at runtime. It exists for exactly one reason: to give PEFT a named child module on the decoder that it can discover via target_modules=["cross_stream"] and replace. Without it, there is nothing for PEFT's LoraModel to walk to. The device-anchor buffer and the weight property are there to satisfy _replace_module's introspection — not because we need them at compute time.

Why we can't host the LoRA on a real nn.Linear. Tempting alternative: add a real nn.Linear(H, H, bias=False) with frozen-zero weight as the host, list it in target_modules, and let stock peft.tuners.lora.Linear wrap it. Stock PEFT's forward would then compute 0·h_base + B(A(h_base)) — the right math. The trade is bad: a frozen H×H weight per layer with no functional role (≈9.4M params/layer at 3B scale, ≈350M across 36 layers), a full-rank H×H matmul per forward whose output we throw away, and the decoder still has to route that linear's output into h_adapt rather than h_base — so the SR-specific call site at decoder_hf.py:145 doesn't actually go away. The savings (deleting CrossStreamLora) are ~150 lines of mechanical LoraLayer conformance. Not worth it.

What CrossStreamLora actually adds vs stock Linear. The delta computation (cross_stream_lora.py:209-220) is the same arithmetic PEFT does — B(A(dropout(x))) * scaling summed over active adapters, with optional alora_offsets masking. The custom class only diverges from stock Linear in places where stock Linear would do the wrong thing for a no-op base:

update_layer Branches on DoRA / PiSSA / OLoRA / EVA inits Kaiming-A, zero-B only; warns on advanced inits Advanced inits need a base weight matrix to consult
resolve_lora_variant Returns DoRA / ALoRA variant if configured Returns None ALORA gating is inlined in forward instead

ALORA is not what forces the custom class. PEFT's pre-forward hook injects alora_offsets into any LoraLayer subclass, so CrossStreamLora gets it for free by inheriting LoraLayer. The mask logic mirrors ALoraLinearVariant.forward and would have to live somewhere regardless of how we host the cross-stream weights.

What is irreducibly ours: the dual-stream architecture itself. PEFT has no concept of two parallel hidden-state streams — it only sees standalone modules. The SR decoder's forward (decoder_hf.py:100-152) is the only code that knows "h_base goes into cross_stream, the result is added to h_adapt." That call site is the bridge between PEFT's "input → linear → output" world and shadow residual's "two streams with a base→adapter edge" world.

If you are tempted to delete CrossStream: the question to answer first is "where is the nn.Linear whose input is h_base and whose output gets added to h_adapt?" There isn't one, and inventing one costs more than the wrapper saves.

9.2 One architecture, conditional dual-stream forward

The base model is always ShadowResidualForCausalLM, regardless of whether cross_stream is in target_modules. Construction does not branch — _build_sr_base always loads upstream GraniteMoeHybridForCausalLM, instantiates ShadowResidualForCausalLM(config), and runs transfer_base_weights to slice fused→unfused. A CrossStream site is always installed on every decoder layer. get_shadow_residual_peft_model calls _register_cross_stream unconditionally so PEFT will install CrossStreamLora and ShadowResidualLora wrappers as appropriate.

What does branch is the runtime forward path. The SR model computes a flag cross_stream_active at the top of forward by walking the layer stack and asking each cross_stream module: "are you a CrossStreamLora wrapper rather than a bare CrossStream?" If the answer is no everywhere, the model takes the adapter-only path; if the answer is yes anywhere, the dual-stream path runs.

ConfigurationArchitectureForward pathPer-layer compute
"cross_stream" ∈ target_modules ShadowResidualForCausalLM Dual-stream: maintains (h_base, h_adapt); every Q/K/V/O/MLP projection runs twice with stream-gated wrappers (base call frozen, adapter call with delta); per-stream K/V caches keep the base trunk's attention reads adapter-free; cross-stream injection at end-of-layer ≈2× attention + MLP vs plain Granite
"cross_stream" ∉ target_modules ShadowResidualForCausalLM (same class) Adapter-only early-exit: only h_adapt is computed; one Q/K/V/O/MLP pass with the LoRA delta firing; base stream is not maintained Equal to plain Granite + the wrapped LoRA deltas

Why a single architecture is sound. The base trunk exists to feed the cross-stream edge: h_adapt += W_cross(h_base). Without a CrossStreamLora installed there is no consumer of h_base — cross_stream(h_base) ≡ 0 — so the base trunk's contribution to every downstream computation is zero. Computing it would be pure redundant work. The early-exit drops the base stream and runs the adapter path alone, which is what users training "LoRA on the SR architecture without cross-stream" actually want. Cross-stream is the only mechanism that couples base→adapter, so its presence/absence is the right signal for the gate.

9.3 The adapter-only early-exit

The early-exit collapses the dual-stream forward to adapter-only when no CrossStream site is wrapped. The base stream is not what survives — the adapter is. The adapter is what the user is training when they configure target_modules=["q_proj", ...] without cross-stream, so it is the path that has to keep running.

What gets skipped

  • The base Q/O projection calls. The decoder layer takes the cross_stream_active=False branch and runs a single Q/K/V/O pass under stream_context("adapter").
  • The base MLP forward. Only one gate_proj/up_proj/down_proj pass runs, on normed_adapt, under stream_context("adapter").
  • The self.cross_stream(h_base) call at end-of-layer — skipped entirely (no consumer of h_base, and there is no h_base).
  • The torch.cat([h_base, h_adapt]) / input_layernorm / post_attention_layernorm fusion — replaced with a single input_layernorm(h_adapt).
  • The h_base = inputs_embeds initialization at the top of the decoder loop. Only h_adapt is maintained.

What is not skipped

  • LoRA wrappers on q_proj/k_proj/v_proj/o_proj/MLP projections still fire on the single pass. ALORA gating still applies via PEFT's pre-forward hook on every LoraLayer.
  • The final-step gate torch.where(adapter_indices > 0, h_adapt, h_base) is gone. The forward returns self.norm(h_adapt) directly. Removing it was the Phase 1 hotfix that restored autograd flow into the LoRA delta in unconditional training; it did not change the dual-stream KV cache invariants (§9.4).

Per-layer compute when the early-exit fires

q = q_proj(normed_adapt);  k = k_proj(normed_adapt);  v = v_proj(normed_adapt)
attn = attention(q, k, v);  h_adapt += residual_multiplier * o_proj(attn)
mlp = down(act(gate(normed_adapt)) * up(normed_adapt))
h_adapt += residual_multiplier * mlp

Every projection's wrapper fires its LoRA delta. The result is "plain LoRA on Granite Switch" — the SR architecture without the dual-stream surcharge.

Subtle: PEFT must already have run before the gate is meaningful. The cross_stream_active check asks "is this CrossStream wrapped?" — which is only true after get_peft_model has installed its wrappers. Forwarding through the bare SR base before get_peft_model always takes the adapter-only early-exit path (because no CrossStream is wrapped yet, and no Q/O/MLP wrapper either, so the LoRA delta on every wrapper is the identity).

9.4 Frozen base — Q, K, V, O, and MLP all preserved

The base trunk is frozen end-to-end. Every projection — Q, K, V, O, and the SwiGLU MLP — is bit-equivalent to the unadapted base model's forward at every layer. There is no K/V exception.

How the freeze is enforced. The decoder layer computes the base stream's Q, K, V, O, and MLP inside stream_context("base"). Each call hits a ShadowResidualLora wrapper, which checks the contextvar at the top of forward: 

def forward(self, x, *args, **kwargs):
    if current_stream() == "base":
        kwargs.pop("alora_offsets", None)
        kwargs.pop("adapter_names", None)
        return self.base_layer(x, *args, **kwargs)   # frozen-base path
    return super().forward(x, *args, **kwargs)        # stock peft path

Under "base" the wrapper returns base_layer(x) only — no LoRA delta, no ALORA, no DoRA. Under "adapter" (default) it delegates to stock peft.tuners.lora.Linear.forward, which adds the LoRA delta with whatever variants are configured. Every Q/K/V/O/MLP projection is called twice per layer — once inside each context — so the same wrapper instance fires the delta on the adapter call and skips it on the base call.

Per-stream K/V caches. ShadowResidualAttention.forward takes two DynamicCache arguments: past_key_values_base for the frozen base, and the user-facing past_key_values for the adapter. The base K/V (computed under stream_context("base") on normed_base) writes into past_key_values_base; the adapter K/V (computed under stream_context("adapter") on normed_adapt) writes into past_key_values. Each attention call reads only from its own cache, so a K/V LoRA delta on the adapter never reaches the base attention's K/V — the contamination that the earlier "single shared K/V" design carried is gone. ShadowResidualModel allocates the second cache transparently when entering the dual-stream branch and does not surface it through BaseModelOutputWithPast; the user-facing cache contract is unchanged.

Cost. The dual-stream path now pays a 2× K/V projection cost (one call per stream instead of one shared call) and stores two KV caches instead of one. Both costs are confined to the dual-stream path; the adapter-only early-exit (§9.3) is unaffected and continues to use a single Q/K/V/O/MLP pass with one cache. The trade-off favours correctness — the base trunk's attention reads are now strictly adapter-free, regardless of what the user puts in target_modules.

What is bit-identical to the unadapted base model:

  • Q, K, V, O, and MLP on the base stream: bit-identical for all training configurations. The wrappers are bypassed under "base", regardless of whether the projection is in target_modules.
  • The base attention's K/V cache reads: bit-identical, because past_key_values_base only ever receives K/V from the frozen base call.
  • Cross-stream injection at end-of-layer: this intentionally diverges h_adapt from h_base; it does not touch h_base.
Glossary.
  • hbase / "base trunk" — the frozen residual stream. Q/K/V/O/MLP on it are bit-equivalent to the unadapted base model under all training configurations (§9.4).
  • normed_base — input_layernorm(hbase) or post_attention_layernorm(hbase). The literal tensor that goes into the base call of Q, K, V, O, and MLP.
  • past_key_values_base — the second DynamicCache the dual-stream forward allocates for the base stream. Holds Wkv·normed_base per layer, never receives any adapter delta. Disjoint from the user-facing past_key_values.
  • stream_context("base"|"adapter") — a contextvar set by the decoder around each per-stream projection call. "base" tells ShadowResidualLora to skip the LoRA delta; "adapter" (default) tells it to apply the delta normally.
  • "unadapted base model" — the original Granite checkpoint with no LoRA wrappers and no SR machinery. Coincides with the base trunk's Q/K/V/O/MLP under all configurations.
