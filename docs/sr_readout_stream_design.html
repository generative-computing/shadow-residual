SR Read-out Stream — empty-adapter-stream design

A proposed Shadow-Residual variant where the adapter stream carries no activations of its own — only the per-layer Wcross injection from the base, carried forward through an inter-layer RMSNorm.
Status: implemented and CPU-tested; Vela jobs not yet launched (blocked on getting the code to the pods, §10). Sections 1–5 are the original design (unchanged). Section 6 records how every open question was resolved, §7 the implementation, §8 the experiment and evaluation protocol, §9 the results, and §10 the issues hit along the way. For the current (shared-base-K/V) design see sr_architecture_explainer.html.
Branch feature/different-arch. Config switch: adapter.adapter_stream: readout (default full = today's SR, untouched).
base stream — frozen full transformer adapter stream — read-out only cross-stream injection Wcross (B·A, trainable) RMSNorm γ (trainable)

1. The idea in one line

In today's SR the adapter stream is a second full transformer: it runs its own (LoRA-adapted) attention and MLP, and also receives the cross-stream injection from the base. This proposal strips the adapter stream down to nothing but the injection. The adapter stream never attends and never runs an MLP; the only thing that writes into it is W_cross(h_base_output), accumulated layer over layer through an RMSNorm. The base stream is the full, frozen base model — unchanged.

h_adaptl+1  =  RMSNorml( h_adaptl )  +  Wcross,l( h_base_outputl )
h_adapt0 = embeds × embedding_multiplier   (clone of the base seed, as in current SR)
logits = lm_head( norm( h_adaptN ) ) / logits_scaling   (only the adapter stream reaches the head)
  • base h_base_outputl — the base stream's layer-l output (after attention + MLP residuals); bit-identical to the unadapted base model.
  • adapter RMSNorm(h_adaptl) — the adapter carry from below, renormalized. This replaces the running sum, so the adapter state is unit-scale at every layer rather than an ever-growing residual.
  • cross Wcross,l(·) — the rank-R B·A injection; the sole trainable projection.

2. Per-layer compute graph

One decoder layer. Left (blue): the base stream runs the full frozen Q/K/V/O + MLP and produces h_base_output — bit-identical to the unadapted base, and the owner of the single shared K/V cache. Right (red): the adapter stream does nothing of its own: its carry is just RMSNorm(h_adapt). Gold: the only write into the adapter stream is W_cross(h_base_output). The next-layer adapter state is RMSNorm(h_adapt) + W_cross(h_base_output).
No adapter K/V, no adapter attention. Because the adapter stream never attends, token-to-token mixing happens entirely inside the frozen base. The adapter can only mix base information across layers (by stacking per-position read-outs), never across positions on its own. That is the defining constraint of this design.

3. Inter-layer recurrence

Zooming out: the base lane is the ordinary frozen transformer; the adapter lane is a renormalize-then-inject recurrence. RMSNorm sits on the adapter residual between layers, so each adapter state is unit-scale before the next base read-out lands.

The base lane is the unadapted frozen transformer; its layer outputs are read out by each layer's W_cross and injected into the adapter lane. The adapter lane renormalizes its carry (RMSNorm) before adding the next read-out. After the last layer the base state is discarded; only norm(h_adaptN) reaches the head — exactly as in current SR.

The base stream, shared-base-K/V, and the frozen-base invariant are all unchanged. The structural difference is confined to the adapter side: it stops running its own attention/MLP and becomes a renormalized accumulator of W_cross injections.

5. Why this shape — and the trade-offs

  • Tiny trainable footprint. Per layer: cross_stream.lora_A [R,H] + cross_stream.lora_B [H,R] + one RMSNorm γ [H]. No Q/K/V/O/gate/up/down LoRA at all.
  • RMSNorm bounds the stream. The carry is renormalized every layer, so the adapter state stays unit-scale no matter how many injections accumulate or how large h_base_output grows in deep layers. Trade-off: early-layer injections are repeatedly renormalized as later ones stack on, so the stream is biased toward recent (deeper-layer) base information.
  • A linear read-out of the base trajectory. The whole bet is that a learned low-rank read-out of the base's layerwise outputs — with cross-position mixing done entirely by the frozen base — is expressive enough for the target tasks. If it isn't, the lever is rank R (or re-admitting adapter attention).

6. Implementation sketch & open questions

These are the concrete hooks a later implementation would touch — recorded here so the design can be critiqued before any code is written.

ConcernWhere / how
Drop adapter attention + MLPdecoder_hf.py: the adapter branch stops calling self_attn / mlp on normed_adapt; it only computes the carry. Base branch unchanged. Shared K/V stays (computed from the base stream).
Inter-layer RMSNormNew per-layer GraniteMoeHybridRMSNorm(H) applied to h_adapt at layer entry, before the W_cross add.
W_cross siteUnchanged — already a stock-LoRA-wrapped frozen zero-init nn.Linear (CrossStream). Reads h_base_output (post-MLP), same injection point as today.

The RMSNorm γ is the one new trainable that isn't LoRA. W_cross fits the stock-PEFT "adapter = LoRA on target_modules" mould, but the per-layer RMSNorm γ is a plain trainable parameter. It would need either a modules_to_save entry in the LoraConfig (so PEFT saves/loads it alongside the LoRA tensors) or a small custom module. This is the main packaging question to resolve before implementing.

Open design points (as originally posed)

  • Non-residual carry, on purpose? As written, RMSNorm(h_adapt_l) replaces the running sum rather than adding to it. An alternative keeps a true residual (h_adapt_l + …). Current spec is the renormalized-carry (non-residual) form.
  • RMSNorm scope. One γ per layer (as drawn) vs. a single shared γ.
  • Seed. h_adapt_0 is the embedding clone (matches current SR); the alternative seed is zero (“truly empty” adapter stream).

All three are resolved in §6b below. The spec as drawn was implemented as-is: renormalized carry, one γ per layer, embedding seed.

6b. Design decisions (resolved)

QuestionDecisionWhy
Carry form Renormalized (non-residual): hl+1 = RMSNorml(hl) + Wcross,l(hbl) This is the design under test. A residual variant would be a different experiment; it is listed as a follow-up ablation, not mixed in.
γ scope One γ per layer ([H], 40 of them on 4.2-3B), initialised to 1 As drawn. Init 1 = an identity RMSNorm, the standard init. Per-layer γ also lets the model learn how much of the carry each layer keeps vs. overwrites, which offsets the “recent-layer bias” trade-off (§5).
Seed Embedding clone, as current SR It keeps the token identity in the stream (it reaches the head through 40 renormalizations, scaled by ∏γ). A zero seed would make layer 0's RMSNorm(0) degenerate (it is 0 · rsqrt(eps) = 0, but the gradient path is poor). It is kept as a follow-up ablation.
Where Wcross reads h_base_outputl: the base residual after attention + MLP of layer l Same site as current SR (decoder_hf.py: cross_stream(h_base) after the MLP add).
Init ⇒ what the untrained model computes LoRA B = 0, so Wcross = 0, and with γ = 1 the adapter stream is RMSNorm40(embeds): the head sees normalized embeddings, not the base output. Important difference from current SR. At init, current SR's adapter stream equals the base stream (its own attention/MLP run the frozen weights, so it reproduces the base model exactly), and training starts from base-model quality. The read-out stream starts from a bigram-like model (logits from embeddings only) and must learn to inject the base trajectory through Wcross. This is inherent to the design (“the adapter stream carries no activations of its own”). It is the main risk, and the reason for the learning-rate and rank choices below.
Bare model / disable_adapter() Unchanged: the single-stream forward_bare path Invariant 3 (bare == unadapted base) holds. The read-out flag only changes the dual-stream branch.
K/V Base-only, one cache (unchanged) The adapter stream has no Q, so K/V is consumed only by the base stream. The KV cache is identical to an unadapted base model's.
Packaging the γ (the §6 warning) Stock PEFT modules_to_save=["readout_norm"] Each decoder layer owns a readout_norm RMSNorm (frozen, γ=1, a no-op until wrapped). PEFT's stock ModulesToSaveWrapper makes a trainable copy per adapter, saves it as ...readout_norm.weight in adapter_model.safetensors, and restores it on PeftModel.from_pretrained. There is no custom PEFT code, which keeps the repo's “100% stock PEFT” property. The frozen original stays at γ=1, so disable_adapter() falls back to it.
How the forward knows it is in read-out mode config.adapter_stream = "readout" (model-config attribute, set by build_sr_config) Like share_moe_routing: it is a forward-path choice, not a weight. train.py records "adapter_stream": "readout" in adapter_config.json, and the serving path (generation_utils.read_adapter_stream_from_adapter) reads it back, so the adapter describes itself. Loading a read-out adapter onto a full base fails loudly (the readout_norm key and the missing q/o/MLP LoRA keys do not match).
Compute saved The adapter stream does no attention and no MLP Per layer, current SR runs ~2× the base FLOPs (two attention Q/O paths + two MLPs). Read-out runs ~1× base + one rank-R injection + one RMSNorm. Activations are about half of current SR's.

Trainable parameter budget (Granite 4.2 3B: H = 2560, 40 layers)

VariantPer layerTotal
Current SR (q,o,gate,up,down r=32 + cross r=32) q 2·32·2560 + o 2·32·2560 + gate/up 2×32·(2560+8192) + down 32·(8192+2560) + cross 2·32·2560 ≈ 1.52 M ≈ 60.9 M
Read-out, cross r=32cross 2·32·2560 + γ 2560 = 166 400≈ 6.7 M
Read-out, cross r=256 (the arm run here)cross 2·256·2560 + γ 2560 = 1 313 280≈ 52.5 M

Why rank 256 for the main arm. The read-out's only lever is the rank of Wcross (§5: “if it isn't [expressive enough], the lever is rank R”). At r=32 the arm has 9× fewer trainable parameters than vanilla SR, so a loss would be confounded with capacity. r=256 brings the read-out to about 86% of vanilla SR's budget (52.5 M vs 60.9 M). The comparison then mostly tests the architecture (a read-out of the base trajectory vs. a second transformer), not parameter count. Four GPUs per job and no short or queued runs leave room for exactly one arm per intrinsic, so the near-parameter-matched arm is the most informative single choice.

7b. Invariants checked on CPU (pytest)

  • Frozen base stream. In read-out mode with a trained (perturbed) adapter, the base-stream state after every layer is bit-identical to the bare model's layer outputs.
  • The recurrence is exactly the spec. A hand-written reference (h = norm_l(h) + cross_l(hb_l), head on norm(h_N)) matches the model's logits.
  • Bare / disabled == base. disable_adapter() logits equal the bare model.
  • Only cross_stream + γ train. The trainable set is exactly cross_stream.lora_A/B + readout_norm.modules_to_save.default.weight. Every one gets a gradient; nothing else does.
  • Save/load round-trip. save_pretrained → build_sr_base(adapter_stream="readout") + PeftModel.from_pretrained gives identical logits, and γ survives.
  • Gradient checkpointing is exact. Loss and gradients are equal with and without HF checkpointing.
  • KV-cache generation == full recompute. Greedy decode with the cache equals step-by-step decode without it.
  • Rejected configs. q/o/MLP targets in read-out mode, and read-out without cross_stream or without readout_norm.
  • Meta-init path. After the FSDP-style meta build + rank-0 materialize, every readout_norm is exactly 1.

10. Issues & notes log

  • Untrained read-out ≠ base model. See §6b (“Init”). Expect a much higher step-0 loss than vanilla SR (vanilla starts at the base model's loss). This is not a bug; the CPU tests pin the exact recurrence.
  • The local harness checkout's local.env was not read (it holds secrets). The harness is pinned by commit instead, and its scorer files were hash-compared against the local checkout.
  • bf16 γ cannot train. γ sits near 1.0, where bf16 spacing is 2-7 ≈ 0.0078. Adam steps of about lr = 2e-4 round to zero, so a bf16 γ never moves. Fix: the factory keeps the trainable γ copy in fp32 (DDP is fine with mixed dtypes). Under FSDP it warns, and the run needs model.param_dtype: fp32.
  • The harness only checks LoRA weights after loading. hf_generate.unloaded_weights covers only lora_A/B, so a γ that silently failed to load would go unnoticed. scripts/readout_bench_eval.py adds its own check that every saved γ loaded (tested both ways on CPU).
  • Several Claude sessions share one working tree. The shared-A session edits training/train.py (multi-task) in the same checkout. This session's train.py change is two additive lines (pass adapter_stream, record it in adapter_config.json), but committing the file as it stands would sweep in the other session's uncommitted hunks.
  • Blocker: getting the code to the pods. Vela pods clone from GitHub. The repo's CLAUDE.md says never commit or push, while the task asked to push only this session's code, and train.py holds another session's unfinished edits. Training waits on that decision.
