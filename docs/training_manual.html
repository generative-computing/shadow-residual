1. What Shadow Residual is

Shadow Residual (SR) is a PEFT adapter that runs two parallel streams per decoder layer.

Each decoder layer runs:

  • A frozen base stream — bit-exact with the unadapted base model. Q/K/V/O/MLP use the base weights with no delta.
  • A trainable adapter stream — LoRA deltas plus a per-layer rank-R cross_stream injection drawn from the base stream.

Only norm(h_adapt) — the adapter stream's normed hidden state — reaches the LM head. Under the hood SR is an ordinary PEFT adapter; it just requires two custom PEFT module types (CrossStreamLora, ShadowResidualLora) and a dedicated loader.

Crucially, there is no architecture name in the config. Behavior is determined entirely by which fields are set. This manual documents the single training entry point, sr-train, and everything around it.

5. Modes of operation

There is no --mode flag. The mode emerges from two YAML fields: whether cross_stream is in target_modules, and whether invocation_tokens is set.

A

Plain LoRA — single-stream early-exit

cross_stream absent · invocation_tokens unset.

Dual-stream forward is skipped (early-exit path ≈ plain LoRA on Granite). shared_base_kv auto-resolves to false (K/V on the adapter stream; a warning is logged). Reference: lora-qkvo-mlp-r16.yaml.

B

aLoRA — gated activation

cross_stream absent · invocation_tokens set.

The delta stays off until the invocation token sequence appears in the input. Requires task_type="CAUSAL_LM" (schema sets it). Forces HF gradient_checkpointing off; train.py re-enables non-reentrant checkpointing explicitly. Reference: alora-all-linear-r16.yaml.

C

Shadow Residual (dual-stream)

cross_stream present in target_modules.

Dual-stream SR forward engages. shared_base_kv auto-resolves to true (one base-only K/V cache), which forbids LoRA on k_proj/v_proj. Optionally combine with invocation_tokens for gated SR. References: the sr-qo-mlp-*-sharedkv*.yaml configs.

The shared_base_kv auto rule: unset (null) means resolve from target_modules — true if cross_stream is present, else false. An explicit true/false always wins. Because it is not serialized into adapter_config.json, a checkpoint trained with a non-default value must pass the same value explicitly to the loader at serve time.

Also mode-shaping

  • param_dtype — fp32 master weights for 8B/30B stability vs bf16 throughout.
  • runtime.fsdp + accelerate launch — DDP vs FSDP sharding; drives the FSDP-aware post-training generate path.
  • Response-only masking — auto: TRL assistant_only_loss=True when the chat template has {% generation %} markers, else the hand-rolled ResponseOnlyCollator (masks everything before the last assistant marker).

6a. Data preparation

Both training and generation read JSONL. One JSON object per line.

Training / eval row shape

{
  "messages":  [{"role": "user", "content": "..."},
                {"role": "assistant", "content": "..."}],
  "tools":     [...],   // OPTIONAL — passed verbatim to apply_chat_template
  "documents": [...],   // OPTIONAL — passed verbatim to apply_chat_template
  "ground_truth": "..." // OPTIONAL — for eval rows; read by the scorer
}
  • messages is required. tools / documents are forwarded as-is to the chat template — the template (Granite's) renders them; the loader does not reshape.
  • For generation/eval rows, messages should not include a trailing gold assistant turn — put the gold in ground_truth. The generator renders with add_generation_prompt=True.
  • Each row is rendered to a single text column via the chat template. enable_thinking is threaded through here.
Label masking is response-only. Loss is computed on the final assistant turn only. In multi-turn RAG data, masking from the first marker would train the model to reproduce long intermediate factual turns — the collator scans from the end.
Gated (aLoRA) data check: when invocation_tokens is set, sr-train samples the first rows and refuses to start if the invocation token sequence is absent (the adapter would never activate). A partial match logs a warning.

6b. Training — what the script does step by step

  1. Load tokenizer; set pad token and right-padding.
  2. If gated: encode invocation_tokens → IDs, attach to the PEFT config.
  3. Build LoraConfig from the adapter block (to_peft_config).
  4. Build the SR+PEFT model via get_shadow_residual_peft_model (base + adapter streams; shared_base_kv resolved here).
  5. For gated SR: enable non-reentrant gradient checkpointing + enable_input_require_grads.
  6. Load train/val datasets; run the aLoRA sanity check if gated.
  7. Build SFTConfig; pick the response-only masking path (assistant_only_loss vs collator).
  8. SFTTrainer.train() with early-stopping + stop-on-NaN callbacks.
  9. Save adapter + tokenizer; guard against a sharded/non-consolidated save.

6c. Generation

run_generation in generate.py is the single source of truth. It is called two ways:

  • Post-training (in train.py): uses the in-memory PEFT model, no reload. Under FSDP it dispatches to run_generation_under_fsdp (gather FULL_STATE_DICT → tear down shards → rebuild non-FSDP on rank 0 → generate). Non-FSDP: only rank 0 generates.
  • Standalone CLI: loads a saved checkpoint from disk via the SR loader, then generates. Useful to give generation a clean CUDA context at 30B.
python -m shadow_residual.training.generate \
    --config path/to/training_config.yaml \
    --checkpoint /path/to/saved/adapter \
    [--data eval.jsonl]     # defaults to cfg.generation.input_path
    [--out predictions.jsonl]  # defaults to <checkpoint>/<output_filename>
    [--limit N] [--debug-generate 0.01]

Output rows preserve the input row verbatim and add one key, generated_content. Batch size halves on OOM down to 1. Left-padding is applied for generation and restored afterward.

7. Serving / evaluation

Load through the SR loader — not PeftModel.from_pretrained, which can't re-register SR's custom modules.

from shadow_residual.peft_shadow_residual import load_shadow_residual_peft_model
model = load_shadow_residual_peft_model(
    base_id, adapter_path,
    torch_dtype=...,
    shared_base_kv=<same value used at training>,  # not serialized!
)

Answerability eval:

python -m shadow_residual.eval.answerability_eval --mode peft \
    --base-model <id> --adapter <path> …

--mode peft is standalone. --mode switch / --mode vllm require the optional granite-switch dependency.

8. Invariants — do not break these

  1. Frozen base stream. Never let a LoRA delta reach a stream_context("base") call. merge_and_unload is disabled on purpose.
  2. Disjoint vs shared K/V. Disjoint = two caches; shared = one base-only cache, no K/V LoRA. Shared is auto-default when cross_stream is present.
  3. ALORA three-knob rule. invocation_tokens + task_type="CAUSAL_LM" + cross_stream must all be set for gated SR; missing any one silently degrades to unconditional LoRA.
