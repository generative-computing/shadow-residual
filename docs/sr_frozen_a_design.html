SR-FrozenA: Shadow Residual with shared, compression-derived, frozen LoRA A matrices

Branch feature/different-arch. Status and results are at the bottom (§9–§11). This doc is updated as the work proceeds.

The idea. In a normal SR adapter every LoRA site W + (α/r)·B·A learns both A (r×in) and B (out×r). Here A is not learned. It is precomputed once from the frozen base model with a model-compression method and frozen. Only the B matrices are trained. The same A is shared by every LoRA site that reads the same input tensor. Then the four benchmark adapters (answerability, guardian_core, query_clarification, requirement_check) are trained and compared with regular SR.

1. Background: what regular SR trains

SR runs two streams per decoder layer: a frozen base stream (identical to the unadapted base) and an adapter stream. K/V come from the base stream only and are shared. The reference SR config for the benchmark (sr-qo-mlp-r32-c32-sharedkv-g42.yaml) puts stock PEFT LoRA, r=32 and α=64, on these sites in every layer:

SiteInput it reads (adapter stream)W shape (out×in) Granite-4.2-3B
q_projx₁ = input_layernorm(h_adapt)2560×2560
o_projx₂ = attention output (concat heads)2560×2560
gate_projx₃ = post_attention_layernorm(h_adapt)8192×2560
up_projx₃ (same tensor as gate)8192×2560
down_projx₄ = silu(gate)·up2560×8192
cross_streamx₅ = h_base at the end of the layer (base residual)2560×2560, W≡0 (frozen zero site)

Base model: ibm-research/granite-4.2-3b-prerelease-r260622a. Dense, 40 layers, hidden 2560, MLP 8192, 40 Q heads and 8 KV heads, untied lm_head. Regular SR has about 30.5M trainable parameters. The saved vanilla SR adapter is 121,961,048 bytes in fp32, which matches.

2. Literature: how to pick a frozen A

Before choosing, I searched the model-compression literature and the frozen-A PEFT literature. These are the relevant results:

LoRA-FA (Zhang et al. 2023, arXiv 2308.03303)Freeze the down-projection A (random init) and train only B. Accuracy is close to LoRA and activation memory is lower.Supports training only B. Their A is random, not derived from the model.

2.1 The chosen method: input-whitened truncated SVD, with a shared basis per input tensor

For a linear map y = W x with calibration inputs X ∈ ℝ^{N×in}, SVD-LLM solves

  min_{rank(W')≤r} ‖ W Xᵀ − W' Xᵀ ‖_F      with  C = XᵀX / N = S Sᵀ  (Cholesky, S lower-triangular)
  W S = U Σ Vᵀ   ⇒   W' = U_r Σ_r · (V_rᵀ S⁻¹)
                          └─B₀─┘   └──A──┘   (out×r)·(r×in)

So the compressed layer is "down-project with A = V_rᵀ S⁻¹, then up-project with B₀ = U_rΣ_r". A is the r-dimensional input subspace that matters most for this weight's output, measured on real activations. That is the projection to freeze. In SR-FrozenA, B starts at zero (LoRA init, so step 0 is identical to the base), learns in the subspace A selects, and B₀ is discarded.

Shared basis for a group of weights reading the same input (Basis Sharing):

  W_G = [W₁; W₂; …] (stacked along out)      e.g. gate+up → 16384×2560
  W_G S = U Σ Vᵀ   ⇒   A_G = V_rᵀ S⁻¹   is shared by every site in G
  Exact identity: ‖(W_G − W_G') Xᵀ‖² = Σᵢ ‖(Wᵢ − Wᵢ') Xᵀ‖², so A_G is the best
  shared rank-r input projection for the group's combined output error.

Scaling. V_rᵀS⁻¹ maps whitened inputs to an orthonormal basis: A C Aᵀ = I_r. Over the calibration data, each of the r features A x has unit variance and they are uncorrelated. That is the right conditioning for training B alone, because every feature reaches B at the same scale. Kaiming-random A gives features whose scale depends on the input norm.

Sites with no informative weight, namely cross_stream (W≡0, reads h_base): whitened SVD is undefined because WS=0. Here I use the ESPACE/EVA choice, the top-r principal components of the input, scaled to unit variance: A = Λ_r^{-1/2} P_rᵀ with C = P Λ Pᵀ. This is the same "unit-variance, max-energy subspace" criterion with the weight term dropped.

3. Design: which sites share which A

Group (per layer)SitesCalibration input covarianceWeight usedA recipe
attn-inq_projC₁ of x₁W_qwhitened SVD (SVD-LLM)
attn-outo_projC₂ of x₂W_owhitened SVD
mlp-ingate_proj, up_proj (shared A)C₃ of x₃[W_g; W_u]whitened SVD of the stacked weights (Basis Sharing)
mlp-outdown_projC₄ of x₄ (8192×8192)W_dwhitened SVD
crosscross_streamC₅ of h_base(W≡0)unit-variance PCA (ESPACE/EVA)

Why share only within the same input tensor. A single A for every site in the adapter is not possible: o_proj and down_proj read different spaces (attention output; 8192-dimensional MLP hidden), so one matrix cannot be a projection for both. The user's "shared A for all LoRA matrices" therefore becomes: no A is learned, and one A is shared by all sites that read the same tensor. Within a layer, gate and up already read the same x₃. Basis Sharing found that sharing across layers works for input-side projections (Q/K/V/gate/up) and hurts for O/down. A cross-layer A for q/gate/up/cross is recorded in §8 as a follow-up ablation. It is not in the main run.

Calibration set. The covariance is computed from the base stream of the unadapted base model on a task-agnostic mix of all four intrinsics' training rows: an equal share of each, 512 rows per intrinsic, 2048 rows total, truncated to 2048 tokens, all non-pad positions, in fp64. One A set serves all four adapters, which is what makes it a property of the base model and not of each adapter. Each adapter still trains its own B. Using the base stream for the adapter-stream inputs is exact at step 0 (the streams are identical when B=0). It stays close later because the adapter is a low-rank perturbation. This is the standard calibration choice in SVD-LLM, ESPACE and CorDA.

Numerics. C + εI with ε = 1e-6·mean(diag C) before Cholesky, as in the SVD-LLM fix for non-positive-definite cases. The SVD of W·S runs in fp64 on GPU and A = V_rᵀ S⁻¹ uses a triangular solve, never an explicit inverse. A is stored in fp32 and cast to the model dtype at load.

4. What changes in training (implementation)

  • The PEFT model stays 100% stock. A is installed into the existing lora_A.default.weight parameters and given requires_grad=False. The saved adapter is an ordinary PEFT LoRA checkpoint (A and B both saved), so PeftModel.from_pretrained on a build_sr_base base loads it with no new code. The benchmark's HF+PEFT SR path (hf_generate.py) and its loaded-weights check work unchanged.
  • New config field adapter.frozen_a: {path: <dir>}. The dir holds frozen_a.safetensors (keys layers.{ℓ}.{site}, fp32 r×in) and manifest.json (recipe, rank, calibration stats, per-group retained output energy).
  • Where A is installed: after get_shadow_residual_peft_model. On the FSDP rank-0-materialize path A is copied after the LoRA reset and before FSDP's sync_module_states broadcast. On every non-FSDP rank it is copied directly. Freezing is applied on every rank before the Trainer builds the optimizer, so A never enters AdamW. fsdp_use_orig_params: true (already set) lets FSDP flat-params mix frozen and trainable parameters.
  • Guard: after training, rank 0 checks that the saved lora_A tensors equal the installed A exactly. A frozen A that moved means a bug, and the job fails.
  • New script shadow_residual.training.compute_frozen_a (one GPU). It runs forward hooks on the base model to accumulate XᵀX per input group, then whitened SVD or PCA per group, and writes the A dir and manifest. It also reports the fraction of the whitened output energy each r-dim A keeps (Σ_{i≤r} σᵢ² / Σ σᵢ²), a cheap diagnostic of how much the frozen subspace can express.

7. Hypotheses

  1. H1 (main). SR-FrozenA comes within about 1 point of vanilla SR on each intrinsic while training 40% fewer parameters. All four tasks are short label or short-output classification-style tasks, which earlier SR sweeps found saturate at low rank (see the rank-grid notes).
  2. H2. The whitened-SVD A beats a random frozen A (LoRA-FA). Planned ablation, §8.
  3. H3 (risk). down_proj and cross_stream lose the most. Their inputs are high-dimensional or heavy-tailed, so a fixed 32-dim subspace keeps a small energy fraction. The manifest's retained-energy numbers will show whether this is plausible.

8. Follow-ups not in this run

  • Random-frozen-A control (LoRA-FA) at the same rank, which isolates "compression-derived" from "frozen".
  • Cross-layer shared A for the input-side groups (Basis Sharing groups of 2–4 adjacent layers).
  • Per-task calibration (A from each task's own rows, CorDA "instruction-previewed") compared with the shared task-agnostic A.
  • Higher rank at equal trainable budget. B-only at r=53 equals vanilla's parameter count.
