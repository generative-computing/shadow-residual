SR-FrozenA: Shadow Residual with shared, compression-derived, frozen LoRA A matrices

Branch feature/different-arch. Status and results are at the bottom (§9–§12). §13 reviews the literature on ways to instantiate the LoRA A matrix. This doc is updated as the work proceeds.

The idea. In a normal SR adapter every LoRA site W + (α/r)·B·A learns both A (r×in) and B (out×r). Here A is not learned. It is precomputed once from the frozen base model with a model-compression method and frozen. Only the B matrices are trained. The same A is shared by every LoRA site that reads the same input tensor. Then the four benchmark adapters (answerability, guardian_core, query_clarification, requirement_check) are trained and compared with regular SR.

1. Background: what regular SR trains

SR runs two streams per decoder layer: a frozen base stream (identical to the unadapted base) and an adapter stream. K/V come from the base stream only and are shared. The reference SR config for the benchmark (sr-qo-mlp-r32-c32-sharedkv-g42.yaml) puts stock PEFT LoRA, r=32 and α=64, on these sites in every layer:

SiteInput it reads (adapter stream)W shape (out×in) Granite-4.2-3B
q_projx₁ = input_layernorm(h_adapt)2560×2560
o_projx₂ = attention output (concat heads)2560×2560
gate_projx₃ = post_attention_layernorm(h_adapt)8192×2560
up_projx₃ (same tensor as gate)8192×2560
down_projx₄ = silu(gate)·up2560×8192

Base model: ibm-research/granite-4.2-3b-prerelease-r260622a. Dense, 40 layers, hidden 2560, MLP 8192, 40 Q heads and 8 KV heads, untied lm_head. Regular SR trains 60,948,480 parameters, as print_trainable_parameters reports in the vanilla job logs. The saved adapter is 121,961,048 bytes because it is stored in bf16.

Before choosing, I searched the model-compression literature and the frozen-A PEFT literature. These are the relevant results:

2.1 The chosen method: input-whitened truncated SVD, with a shared basis per input tensor

For a linear map y = W x with calibration inputs X ∈ ℝ^{N×in}, SVD-LLM solves

  min_{rank(W')≤r} ‖ W Xᵀ − W' Xᵀ ‖_F      with  C = XᵀX / N = S Sᵀ  (Cholesky, S lower-triangular)
  W S = U Σ Vᵀ   ⇒   W' = U_r Σ_r · (V_rᵀ S⁻¹)
                          └─B₀─┘   └──A──┘   (out×r)·(r×in)

So the compressed layer is "down-project with A = V_rᵀ S⁻¹, then up-project with B₀ = U_rΣ_r". A is the r-dimensional input subspace that matters most for this weight's output, measured on real activations. That is the projection to freeze. In SR-FrozenA, B starts at zero (LoRA init, so step 0 is identical to the base), learns in the subspace A selects, and B₀ is discarded.

Shared basis for a group of weights reading the same input (Basis Sharing):

  W_G = [W₁; W₂; …] (stacked along out)      e.g. gate+up → 16384×2560
  W_G S = U Σ Vᵀ   ⇒   A_G = V_rᵀ S⁻¹   is shared by every site in G
  Exact identity: ‖(W_G − W_G') Xᵀ‖² = Σᵢ ‖(Wᵢ − Wᵢ') Xᵀ‖², so A_G is the best
  shared rank-r input projection for the group's combined output error.

Scaling. V_rᵀS⁻¹ maps whitened inputs to an orthonormal basis: A C Aᵀ = I_r. Over the calibration data, each of the r features A x has unit variance and they are uncorrelated. That is the right conditioning for training B alone, because every feature reaches B at the same scale. The overall scale also matters: under AdamW, the output change per step on B is proportional to ‖A x‖. So each group's A is multiplied by s = √(tr C / (3·in)), which is the per-feature standard deviation PEFT's stock kaiming_uniform_(a=√5) lora_A gives on the same inputs (entry variance 1/(3·in)). Then A C Aᵀ = s² I: the features carry the same energy as vanilla LoRA's at step 0, so LR and α transfer unchanged. The only remaining difference from vanilla is which r directions are read, and that they are fixed (feature_scale: kaiming in the manifest).

Sites with no informative weight, namely cross_stream (W≡0, reads h_base): whitened SVD is undefined because WS=0. Here I use the ESPACE/EVA choice, the top-r principal components of the input, scaled to unit variance: A = Λ_r^{-1/2} P_rᵀ with C = P Λ Pᵀ. This is the same "unit-variance, max-energy subspace" criterion with the weight term dropped.

3. Design: which sites share which A

Group (per layer)SitesCalibration input covarianceWeight usedA recipe
attn-inq_projC₁ of x₁W_qwhitened SVD (SVD-LLM)

mlp-ingate_proj, up_proj (shared A)C₃ of x₃[W_g; W_u]whitened SVD of the stacked weights (Basis Sharing)
mlp-outdown_projC₄ of x₄ (8192×8192)W_dwhitened SVD

Why share only within the same input tensor. A single A for every site in the adapter is not possible: o_proj and down_proj read different spaces (attention output; 8192-dimensional MLP hidden), so one matrix cannot be a projection for both. The user's "shared A for all LoRA matrices" therefore becomes: no A is learned, and one A is shared by all sites that read the same tensor. Within a layer, gate and up already read the same x₃. Basis Sharing found that sharing across layers works for input-side projections (Q/K/V/gate/up) and hurts for O/down. A cross-layer A for q/gate/up/cross is recorded in §8 as a follow-up ablation. It is not in the main run.

Calibration set. The covariance is computed from the unadapted base model (the bare SR model) on a mix of all four intrinsics' training rows: 512 rows sampled with a fixed seed from each data_v1/<intrinsic>/train.jsonl, 2048 rows total. Each row is rendered with the trainer's own render_chat, truncated to 2048 tokens, and every non-pad position is accumulated in fp64. No eval rows are used. One A set serves all four adapters, which is what makes it a property of the base model and not of each adapter. Each adapter still trains its own B. Using the base stream for the adapter-stream inputs is exact at step 0 (the streams are identical when B=0). It stays close later because the adapter is a low-rank perturbation. This is the standard calibration choice in SVD-LLM, ESPACE and CorDA.

Numerics. C + εI with ε = 1e-6·mean(diag C) before Cholesky, as in the SVD-LLM fix for non-positive-definite cases. The SVD of W·S runs in fp64 on GPU and A = V_rᵀ S⁻¹ uses a triangular solve, never an explicit inverse. A is stored in fp32 and cast to the model dtype at load.

4. What changes in training (implementation)

  • The PEFT model stays 100% stock. A is installed into the existing lora_A.default.weight parameters and given requires_grad=False. The saved adapter is an ordinary PEFT LoRA checkpoint (A and B both saved), so PeftModel.from_pretrained on a build_sr_base base loads it with no new code. The benchmark's HF+PEFT SR path (hf_generate.py) and its loaded-weights check work unchanged.
  • No shared file is edited. Several sessions edit train.py, factory.py and training_config.py in the same working tree, so the feature is three new files:
    • training/frozen_a.py: the recipes, install_frozen_a, and saved_a_mismatches.
    • training/compute_frozen_a.py: the calibration CLI.
    • training/train_frozen_a.py: an entry point that wraps train.main. It takes --frozen-a <dir> plus every train.py argument and swaps factory.get_shadow_residual_peft_model for a version that installs the A after building. train.py imports the factory lazily inside main(), so the patch takes effect.
    The A dir holds frozen_a.safetensors (keys layers.{ℓ}.{site}, fp32 r×in) and manifest.json (recipe, rank, scale, calibration stats, and per-group retained output energy).
  • Where A is installed: after get_shadow_residual_peft_model. On the FSDP rank-0-materialize path A is copied after the LoRA reset and before FSDP's sync_module_states broadcast. On every non-FSDP rank it is copied directly. Freezing is applied on every rank before the Trainer builds the optimizer, so A never enters AdamW. fsdp_use_orig_params: true (already set) lets FSDP flat-params mix frozen and trainable parameters.
  • Guard: after training, rank 0 checks that the saved lora_A tensors equal the installed A exactly. A frozen A that moved means a bug, and the job fails.
  • New script shadow_residual.training.compute_frozen_a (one GPU). It runs forward hooks on the base model to accumulate XᵀX per input group, then whitened SVD or PCA per group, and writes the A dir and manifest. It also reports the fraction of the whitened output energy each r-dim A keeps (Σ_{i≤r} σᵢ² / Σ σᵢ²), a cheap diagnostic of how much the frozen subspace can express.

7. Hypotheses

  1. H1 (main). SR-FrozenA comes within about 1 point of vanilla SR on each intrinsic while training 44% fewer parameters. All four tasks are short label or short-output classification-style tasks, which earlier SR sweeps found saturate at low rank (see the rank-grid notes).
  2. H2. The whitened-SVD A beats a random frozen A (LoRA-FA). Planned ablation, §8.
  3. H3 (risk). down_proj and cross_stream lose the most. Their inputs are high-dimensional or heavy-tailed, so a fixed 32-dim subspace keeps a small energy fraction. The manifest's retained-energy numbers will show whether this is plausible.

8. Follow-ups not in this run

  • Random-frozen-A control (LoRA-FA) at the same rank, which isolates "compression-derived" from "frozen".
  • Cross-layer shared A for the input-side groups (Basis Sharing groups of 2–4 adjacent layers).
  • Per-task calibration (A from each task's own rows, CorDA "instruction-previewed") compared with the shared task-agnostic A.
  • Higher rank at equal trainable budget. B-only at r=53 equals vanilla's parameter count.

Vanilla SR's update lies 97–99% outside the principal-energy subspace, and is only 1–2× more aligned with it than a random subspace would be. Read with care: LoRA's A moves little from its random init (Zhu et al. 2024), so this mostly says that vanilla adapts through a near-random 32-dimensional read of the input. The principal subspace chosen here is not where its useful update lives.

11. Conclusion

H1 is rejected. SR-FrozenA trains 44% fewer parameters per adapter (34.1M vs 60.9M) and shares one frozen A set across all four adapters. But it loses 2.0–5.4 points on every intrinsic, and every CI excludes 0 (ans −2.67, guard −2.04, qc −5.38, req −4.38). It is also worse than the trained shared A of session 3a884bc0 (−0.65 / −0.50 / +0.36 / −1.37 at −33% params for the family). The frozen A held exactly: the post-save check passed on all four runs.

Why. Compression keeps the input directions that carry the most energy for the base weight's own output. That is the right subspace for reconstructing the base model (SVD-LLM's goal), but not for adapting it:

  • Vanilla SR's learned updates lie 97–99% outside that subspace (§10.3).
  • Restricted to it, B fits the training data faster at first but plateaus at a higher loss on every task (§10.2).
  • For cross_stream, the input PCA of the residual is dominated by massive-activation channels (energy 1.00 in 32 directions, §10.1), so that site reads almost nothing task-relevant.

This matches the minor-component view (MiLoRA, CorDA's knowledge-preserving mode): the principal directions are what the base already uses, and the adaptation signal lives elsewhere.

What is and isn't established. The run shows that this A, the principal compression subspace, is worse than a learned one. It does not yet separate "freezing A" from "choosing the principal subspace". The decisive control is a random frozen A (LoRA-FA) with the same recipe and sharing:

  • If random-frozen ≈ vanilla, the compression subspace is the problem, and the next variant is the minor components (V_{−r:}) or task-calibrated directions.
  • If random-frozen ≈ FrozenA, freezing itself costs 2–5 points at r=32 on these tasks.

That control is now running (§12). It uses the random bank sr_frozen_a/frozen_a_rand_r32_v1 (kaiming draw, gate/up shared), zero-init B, and an otherwise identical recipe.

13. Literature review: what is the optimal LoRA A matrix?

This section is a general LoRA question, independent of SR. For a site W + (α/r)·B·A with A ∈ ℝ^{r×in} (down-projection) and B ∈ ℝ^{out×r}, what should A be? Should it be trained at all, and if so, where should it start? Every entry was checked against its arXiv abstract. Where numbers are quoted, they come from the paper's own tables (arXiv HTML).

Notation: LoRA-One uses the row-vector convention y = xW. Its statements are transposed here so that "A" is always the input-side factor and G is out×in.

Short answer. The best-supported choice is A = the top-r right singular vectors of the task's full fine-tuning gradient G = ∂L/∂W = Σ g xᵀ, estimated from a few batches and suitably scaled (LoRA-One, LoRA-GA, GoRA).
  • Theory: standard LoRA's A drifts toward exactly that subspace, but slowly. LoRA-One shows Θ(ln d / λ) steps from a random start.
  • Practice: LoRA-One beats LoRA, PiSSA, LoRA-GA and LoRA-Pro.
If no gradient is available:
  • The best cheap proxy is the top principal directions of the input activations (EVA). They maximise the expected gradient signal reaching B, and EVA has the best GLUE average among the inits it compares.
  • A random A is a surprisingly strong baseline, even frozen.
  • Taken from the weight alone, the minor singular directions beat the principal ones (MiLoRA vs PiSSA). Principal-weight directions are the worst of the families compared, sometimes below random.

13.1 Does A matter at all? (the asymmetry results)

WorkFindingNumbers
Asymmetry in Low-Rank Adapters (Zhu et al. 2024, 2402.16842) A extracts features and B maps them to outputs. In linear regression, freezing A = Q turns training into least squares on the projected inputs QX, with optimum B* = ΔΣQᵀ(QΣQᵀ)⁻¹. A random Q loses nothing if the input covariance has rank ≤ r, and little if the inputs are redundant. Freezing B instead throws away output directions, which is much worse (Thm 4.3). B-only training also gets a √2-tighter generalization bound. The frozen A is a random orthonormal matrix; PEFT's kaiming draw gives essentially the same results.

  • Exception: on BART summarization, B-only even at 2× rank trails LoRA by about 0.9 R-1 on XSum.
LoRA-FA (Zhang et al. 2023, 2308.03303)Freezing A at its random init (B-only) gives parity with LoRA and full fine-tuning on GLUE, GSM8K, MT-Bench and HumanEval, with lower activation memory.—

Takeaway. A trained A carries much less task-specific information than B, and a random A preserves most of the input information that B needs. Even LoRA-One, which proves A does move toward the gradient subspace, finds that this alignment takes Θ(ln d) steps. So a smart A has to beat a high baseline, and the clearest gains come from faster convergence rather than a better final optimum.

The objectives nest. G = Σ g xᵀ, so the row space of G lies inside the span of the activations x.

  • EVA (activation PCA) is the gradient objective with the output-error signal g dropped.
  • Weight-SVD drops the data and the task.
As the evidence below shows, each step down that chain loses quality.

13.6 Relation to this experiment

The SR-FrozenA A (§2.1) is a weight-reconstruction subspace. The SVD-LLM whitened SVD keeps the input directions that matter most for the base weight's own output. That puts it in the principal family (PiSSA / CorDA-instruction mode), which ranks lowest in §13.3, and it is frozen, so training cannot drift away from it. The 2–5 point loss in §10 and the 97–99% of vanilla's update lying outside that subspace (§10.3) match that ranking. The random-A control (§12) measures the "random ≳ principal" step directly. The literature points to the next candidate as a gradient-derived A: top right singular vectors of the task gradient accumulated over a few batches, as in LoRA-One / LoRA-SB.

14. Data-free A from the base weights: minor singular directions (MiLoRA-style)

Goal (Anton, 2026-11-18): compute a good A candidate from the base weights alone, with one A set shared by all four adapters. There is no gradient or task data. A gradient-derived A needs labels, so it is ruled out.

Choice. Weight-only methods can take the principal directions (PiSSA) or the minor ones (MiLoRA). §13.3 ranks minor > random > principal (MiLoRA's GSM8K ablation: 64.0 / 63.2 / 60.7). Our compression A sits in the principal family and lost to random on guard (§12). So the candidate is the minor right singular vectors of W:

  W = U Σ Vᵀ (thin SVD)   ⇒   A = V_{−r:}ᵀ / √3      (r = 32, the 32 smallest σ)
  gate+up: one shared A from the thin SVD of [W_gate; W_up]   (same sharing as §3)
  down_proj (2560×8192): thin SVD, so the minor directions lie in W's row space, not its exact null space
  • Scale. The rows are orthonormal, scaled by 1/√3, which is the expected row norm of PEFT's kaiming lora_A. That matches the random bank's scale, so in A only the directions differ from §12.
  • Meaning. These are the input directions the base weight is nearly blind to. The adapter adds new reads there instead of re-weighting what the base already reads.
  • cross_stream has W≡0, so there is nothing to decompose. Its A is copied from the random bank (seed 0), so this arm differs from §12 only at the 200 q/o/gate/up/down sites.

Risk. The base may have learned to ignore minor input directions because activations carry little energy there. Then the frozen features A x would be small and B would learn slowly. MiLoRA trains A afterwards, so it can recover from this; here A stays frozen. The training curves will show it if it happens.

Run. Code is frozen_a.weight_svd_a plus training/compute_weight_a.py; the tests are test_weight_svd_a_picks_minor_or_principal_directions and test_weight_bank_covers_every_site_from_weights_only. The bank is sr_frozen_a/frozen_a_minor_r32_v1 (log in minor_calib.log). The jobs are antonp-frzm-{ans,guard,qc,req}, using sr_frozen_a/code_v3/ with B=0 and a recipe identical to §12.

Bank diagnostics (before training). In the minor directions, the weight energy Σσ²(minor 32)/Σσ² is 4e-7 for q, 7e-7 for o and about 0.2% for gate+up and down. So for q/o these are near-null directions of W.

The activation energy those directions read was measured as the per-feature variance diag(A C Aᵀ), with C the input covariance from 32 calibration rows (8 per task, ≤1024 tokens) on CPU (scratch/frza/feature_energy.py, sr_frozen_a/feature_energy_v1.json). Values are relative to the random bank:

The data-free minor directions are not low-energy input directions. They read more activation variance than random, concentrated in a few features. The base weights apparently learned to suppress a few large-variance input channels (the massive-activation channels that also dominated the cross_stream PCA, §10.1), and the minor SVD picks exactly those out. Expected consequences:

  • A higher effective step size on q and gate+up: feature std is about 2.2–2.8× random's.
  • Some of the 32 features read near-constant outlier channels. These act like a bias, so this A may behave like a lower-rank random A.

That confirms the §10 diagnosis: the principal subspace is the wrong place to adapt.
  • No compression strategy beats a random A. Their 4-task means are 0.9–1.2 below random A. Each has at most one significant win (fold on guard, +0.32), and fold and prune lose significantly on ans and req.
  • No strategy is consistent across tasks. Sketch is best on ans but worst on req. Fold is best on guard and qc but loses on ans and req.
  • Why: compressed rows read the outlier channels. The activation variance diag(A C Aᵀ) was measured on 32 calibration rows (sr_frozen_a/feature_energy_compress_v1.json). Relative to random A, the mean feature variance is 2.8–5.2× for prune, 1.7–10.2× for fold and 1.4–2.4× for sketch. The max/min spread across the 32 features reaches 3157 (prune, down), 11219 (fold, down) and 450 (sketch, down), against 21 for random. A few features dominate, so the effective rank is below 32. Sketch is the least skewed compression.
  • Seed noise comes from a parallel session (docs/autopilot/a-compression/: random frozen A, seeds 2–5). The run-to-run SD is 0.94 on qc and 0.58 on req, and about 1 req run in 20 drops by about 7 points. So all qc differences here are within noise. The req losses vs random A (−1.9 / −2.2 / −3.5) are 2–4× the SD of a two-run difference (≈0.82), so they are probably real. No floor was measured for ans or guard.
  • Overall ordering: random A ≈ vanilla ≳ minor ≈ fold ≈ sketch ≈ prune ≫ SVD-LLM. The more an A leans toward the base weight's own structure, the worse it does. The best data-free frozen A on this setup is still a plain random draw.
